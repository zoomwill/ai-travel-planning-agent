# Source Limitations and Reconstruction Policy

The screenshots strongly support the architecture and intended behaviors, but they do not provide the original repository, full dependency versions, credentials, dataset or benchmark artifacts.

Treat them as an architecture and behavior specification, not a byte-for-byte code archive.

Use these labels honestly:

- implemented and tested: an appropriate test was actually run,
- designed: architecture or code exists but production behavior is unverified,
- target: desired metric,
- source example: copied from the source but not validated.
